# 「她知」线上协作指南（零安装·浏览器里直接改）

> 不用装 Python、不用 clone 代码、不用命令行 —— **只要能上网 + 一个 GitHub 账号**，在浏览器里就能改代码、提交、上线。
> 线上地址：https://shezhi.streamlit.app　｜　仓库：https://github.com/lxj20060702-del/shezhi

---

## 0. 先做一次（只做一次）

1. 注册/登录 **GitHub** 账号
2. 把 **GitHub 用户名**发给组长 → 组长在仓库 **Settings → Collaborators → Add people** 邀请你
3. 邮箱里点接受邀请 → 完成（之后你就有权限开分支、提 PR 了）

> 没被邀请也能干活：点仓库右上角 **Fork** 复制到自己账号，改完再提 PR 回来（下面的流程一样）。

---

## 1. 谁改哪个文件（只认领自己的）

| 角色 | 负责文件 |
|---|---|
| 🎨 设计 A | `assets/style.css`、`views/qa_view.py`、`views/kb_view.py` |
| 🎨 设计 B | `views/recommend_view.py`、`views/graph_view.py` |

| ⚙️ 功能 B | `src/recommend.py`、`src/graph.py`、`data/organizations.json` |
| 👑 组长 | `app.py`、`requirements.txt`、`docs/`、合并 PR |

**规则：只改自己那几份文件**；要动别人的先在群里说一声。

---

## 2. 怎么改（两种，按需选）

### 路径 A：网页直接改（最简单，适合改一个文件）

1. 打开 https://github.com/lxj20060702-del/shezhi
2. 一层层点进你要改的文件，例如 `assets/style.css`
3. 点右上角 **✏️ 铅笔图标**（Edit this file）
4. 直接改内容
5. 拉到最下面 **Commit changes**：
   - 说明随便写一句（例：`style: 主色改成紫色`）
   - ⚠️ **一定选第二个选项**：`Create a new branch for this commit and start a pull request`
   - 点 **Propose changes** → 再点 **Create pull request**
6. 完事，等组长合并

### 路径 B：网页版 VS Code（改多个文件 / 看得更舒服）

1. 打开 **https://github.dev/lxj20060702-del/shezhi** ← 浏览器里直接变成 VS Code，能看整个项目
2. 左边点开自己要改的文件，直接打字改（有语法高亮、有中文没问题）
3. 改完按 **Ctrl+Shift+G** 打开「源代码管理」→ 填一行说明 → 点 **✓ Commit**
4. 弹出提示时选 **Create a new branch**（别提交到 main），输入分支名如 `feat/设计A-配色`
5. 回到 https://github.com/lxj20060702-del/shezhi ，会看到黄色条 **Compare & pull request** → 点它 → **Create pull request**

> 新建文件：在 `views/` 右键 → New File，命名 `xxx_view.py`，内容写 `def render(): ...`（新页面要组长在 `app.py` 里接一下）。

## 3. 改完怎么上线

**组长**在 PR 页面看一眼改了什么 → 点 **Merge pull request** → Streamlit Cloud **约 1 分钟自动重新部署** → 刷新 https://shezhi.streamlit.app 就能看到。

改坏了也不怕：组长在 GitHub 上点 **Revert** 就能一键回退。

> 因为线上是「合并即部署」，改完**先看一眼线上页面**再继续下一件事；发现不对立刻在群里说。

## 4. 常用改动示例

**① 换主色（设计 A）**
- 文件：`assets/style.css` → 顶部 `:root { --brand: #6da34d; }` 改成你要的颜色
- 同步：`.streamlit/config.toml` 里的 `primaryColor` 改成同一个色值
- 全站配色、按钮、卡片边框会一起变

**② 改问答页文案/布局（设计 A）**
- 文件：`views/qa_view.py` → 里面 `EXAMPLES = [...]` 是三个示例问题，直接改成你想展示的问题

**③ 加一条政策（功能 A）**
- 文件：`data/policies.json` → 照现有条目复制一份，改内容：

```json
{
  "id": "pol_shebao_2024",
  "topic": "社保医保",
  "title": "……（政策名称）",
  "publisher": "北京市人力资源和社会保障局",
  "effective_date": "2024-01-01",
  "summary": "……（用大白话写 2–3 句，面向看不懂政策的打工人）",
  "source_name": "北京市人社局官网",
  "source_url": "https://……",
  "updated": "2026-09-21"
}
```
- ⚠️ 来源**只能用官方**（gov.cn / 政府部门官网 / 法律法规数据库），并填全 `publisher` + `effective_date` + `source_url`
- ⚠️ JSON 很挑格式：**每条之间要有逗号、最后一条不要逗号**；GitHub 编辑器右侧会有红色波浪线提示语法错误，看到红波浪线千万别提交

**④ 给机构补字段（功能 B）**
- 文件：`data/organizations.json` → 给每个机构补 `"intro"`（简介）与 `"join"`（怎么参与），保持和其他字段一样的写法

## 5. 避坑（很重要）

- 🚫 **不要提交任何密钥 / Key**（仓库是公开的，谁都能看）
- 🚫 **不要改 `app.py`**（组长专属），需要新页面就在群里提
- 🚫 **不要两个人同时改同一个 JSON 文件**（冲突极难解）
- ✅ 改 JSON 后扫一眼有没有红色波浪线
- ✅ 提交时**一定新建分支**，别直接改 main
- ✅ 一次 PR 只做一件事，说明写清楚改了什么（组长好合并）
