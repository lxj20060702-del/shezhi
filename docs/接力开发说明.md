## 1. 新电脑上要准备什么（3 件事，约 10 分钟）

1. **装环境**：Python 3.11+ 、git（云端跑的是 3.14，本地 3.11/3.12 都行）
2. **拉代码**：
   ```bash
   git clone https://github.com/lxj20060702-del/shezhi.git
   cd shezhi
   pip install -r requirements.txt
   ```
3. **建 `.env`**（项目根目录，手动新建，**绝不提交**）：
   ```
   LLM_BASE_URL=https://open.bigmodel.cn/api/paas/v4
   LLM_API_KEY=<同云端 Secrets 里的那把 key>
   LLM_MODEL=glm-4-flash
   ```
   > Key 直接复用现有的那把（在上一台电脑的 `shezhi\.env` 里，或 Streamlit → App settings → Secrets 里就能看到）。
   > 若新电脑拿不到，就登录智谱 BigModel 后台 → API Keys 复制；**不必新建应用、不必改云端配置**。

**登录/权限**：只需要用同一个 GitHub 账号（`lxj20060702-del`）登录，push 时用系统凭据管理器里已存的 GitHub 凭据（或生成一个 Personal Access Token，勾 `repo`）。Streamlit Cloud 用 GitHub 一键登录。

**本地自测**：
```bash
streamlit run app.py     # 打开 http://localhost:8501
```
没配 Key 也能跑（自动降级「检索式抽取答案」），配了 Key 就走 GLM 生成。

## 3. 接力工作流（3 步，改完自动上线）

```bash
# 1. 拉最新
git pull origin main
# 2. 本地改 + 自测
streamlit run app.py
# 3. 上线（推送后云端约 1 分钟自动重新部署，网址不变）
git add -A
git commit -m "feat: 个性化推荐页"
git push origin main
```

**改 Secrets（一般不用动）**：share.streamlit.io → 打开 app → 右下角 **Manage app** → **⋮** → **Settings** → **Secrets** → 改完 **Save changes** → 再 **⋮** → **Reboot app**（不重启不生效）。

### 项目约定（避坑）
- 🚫 绝不提交 `.env`（`.gitignore` 已挡）；Key 绝不写进代码（**仓库是 public**）
- ✅ 改完 `data/*.json` 做一次格式校验：
  ```bash
  python -c "import json;json.load(open('data/organizations.json',encoding='utf-8'));print('ok')"
  ```
- ✅ 多人并行：`git checkout -b feat/xxx` → 开 PR；**同一时间只有一人改 `data/`**（JSON 冲突难解）
- ✅ 新增第三方库要同步写进 `requirements.txt`
- ⚠️ 顺手项：`use_container_width` 将在 2025-12-31 后被移除，建议改用 `width="stretch"`

## 4. 接下来要做的功能（对照需求文档的差距）

> 需求文档里**功能模块共 4 个**：① 智能问答 ② 组织与活动个性化推荐 ③ 知识图谱浏览 ④ 后台数据录入与校验。
> 现状：①③ 已上线，**②④ 没做**。

### P0 · 必做（文档明确要求）
1. **个性化推荐页（功能模块② / 计划 T7）**
   - 输入：性别 / 职业（家政·餐饮·零售·制造）/ 有无子女 / 主要诉求（找工作、讨薪维权、孩子上学、心理支持、文化活动…）
   - 逻辑：匹配 `organizations.json` 的 `tags`/`services`/`target`，命中「他乡的你」等项目一并推荐
   - 输出：推荐卡片（组织 + 能提供什么 + 参与方式 + 来源链接）
2. **政策库扩充**（现只有 3 条）
   - 按 `数据源核实清单.md` 补：**社保/医保、劳动维权（欠薪、工伤）、居住证办理、12348 使用说明**
   - 每条必须有 `publisher` + `effective_date` + `source_url`，只用 gov.cn 系权威源
3. **测试问题集 6–10 题（T9）**
   - 组织类：「XX 组织往年办过哪些女性文艺活动？怎么参加？」→ 必须落到**具体组织 + 组织介绍**
   - 政策类：「外地务工人员在北京怎么申请免费法律援助？」「孩子在京上学需要什么材料？」→ 与官方口径一致
   - 页内加「示例问题」按钮 + 出一份准确率评测结果，供设计文档引用
4. **设计文档 PDF（T11）**，必须包含：
   - 需求分析 / 设计思路 / 功能模块 / **工具平台介绍**
   - 软硬件平台及**版本号**、**AI 大模型名称及版本号**（glm-4-flash）、**AI 生成代码占比**
   - 各开发周期设计过程 + **操作步骤说明** + 测试账号（如设了登录）

### P1 · 加分 + 合规
5. **补齐组织字段**：现有 13 个字段（id/name/aliases/type/target/services/activities/founded/contact/source_name/source_url/tags/updated），**缺「简介」「参与方式」**，`contact` 多为占位 → 按文档 A 节 8 字段补齐
6. **数据后台页（功能模块④）**：上传/编辑 JSON → 校验必填字段、URL 可达、查重、来源完整性
7. **手机端适配**（目标用户是流动女性，主要用手机）：大字号、按钮够大、单列布局
8. **「关于/技术栈」页**：写清工具与平台、版本号、AI 使用声明（设计文档强制项，页面可直接截图）

### P2 · 体验
9. 图谱交互：点节点高亮邻居 / 按标签过滤
10. 问答体验：流式输出、追问、一键复制来源
11. 兜底：大模型超时/失败时页面明确提示
